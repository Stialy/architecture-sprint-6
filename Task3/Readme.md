## Задание 3. Переход на Event-Driven архитектуру

### Проблемы и риски текущей архитектуры

* Обращение к ins-product-aggregator, сервису интерграции со страховыми компаниями, синхронный. 
Сервис формирует синхронные обращения к API страховых компаний, сейчас их 5.
Ожидает получения ответа от всех зарегистрированных компаний и агрегирует их.
Любая задержка или возникщая общибка при запросе данных хотя бы из одного провайдера данных приведет к общей задержке ответа или не возможности его сформировать.
Потребуются повторные запросы для получения актуальных данных.    
* Увеличение количества интеграций увеличит вероятность большого ошибок при работе с сервисом и роста времени ответа сервиса.
* Синхронный API ins-comp-settlement (взаиморасчётов со страховыми компаниями) с большим набором данных (количество оформленных страховок за период)

Паттерн Transactional Outbox считаю нужным использовать в финансовых потоках - расчете возграждения за оформленные страховки и в потоке оформления страховки.
Так в этих потоках потеря информации критична
